# D11: Placement of the public contract records (PublicState, SessionEnd, Error)

- **Status:** proposed
- **Owner:** Person A
- **Reviewer:** Person B
- **Decides:** Xueming (A) and Peyton (B)

## Problem

PRD 2.2 and 21.1 give Person A `contracts/public_v1.openapi.yaml` with the public endpoints and
`Error`, and PRD 9.4 lists `PublicState` as the projection B returns from `commit-plan`. On
`main`, `Error`, `PublicState` and `SessionEnd` are defined only in B's
`contracts/learning_v1.schema.json` (generated by `tools/dev/generate_contract_assets.py`), and
the public contract did not exist. The public API needs one self-consistent definition of each
record without A editing B's file.

## Decision (proposed)

1. `PublicState` and `SessionEnd` stay in B's schema and the public contract references them by
   `$ref` (`learning_v1.schema.json#/$defs/PublicState`, `#/$defs/SessionEnd`). They are B's
   projections of B's state: B decides which fields a learner may see, and the same bytes B
   returns from `commit-plan` and `observe-and-plan` are what A forwards. A compatibility test in
   `tests/integration/response/test_public_api.py` resolves the public references, validates B's
   fixtures (`session_end.json`) through the public contract and fails if a leaked private field
   (mastery, belief, versions) ever appears in the projection.
2. `Error` is defined in A's `contracts/public_v1.openapi.yaml` with the eleven PRD 9.5 codes and
   their HTTP statuses (`x-tutor-http-status`). B's copy in `learning_v1.schema.json` remains the
   internal error record; `tools/response/validate_contracts.py` checks that the public code list
   and statuses equal the PRD table, and the public API maps B's internal codes onto public ones
   (`apps/public_api/clients.py: raise_for_error`). If B later removes `Error` from
   `learning_v1.schema.json`, nothing in A's code changes.
3. The public turn result, public response projection, session view, request bodies and limits
   (8,000 characters per message, 65,536 bytes per request) live only in the public contract.

## Alternatives considered

- **Copy `PublicState` into the public contract.** Rejected: two definitions of one projection
  drift silently (the response schema already carries generated copies of `TeachingPlan`), and B
  would have to review A's file for every projection change.
- **Move `Error` out of B's schema into A's.** Rejected for now: it changes B's file and B's
  fixtures (`state_conflict_error.json`); the reference-plus-check approach gives the same
  guarantee without a cross-owner edit. B may drop its copy later at a minor version.
- **Define everything in one shared file.** Rejected: PRD 2.2 forbids shared implementation
  ambiguity; every file has one owner.

## Codes and behaviors the PRD leaves open (A's choices, for B's review)

| Situation | PRD text | Choice |
|---|---|---|
| `request_id` reused with different content (8.2 step 2 "returns a conflict") | no code named | `409 STATE_CONFLICT`, `retryable: false`; the original request's stored result is unchanged. Proposed addition for v1.1: a dedicated `REQUEST_CONFLICT` code so clients can tell it from a stale version. |
| Another request of the same session still in flight | one pending plan, competing request gets `409 STATE_CONFLICT` (8.3) | `409 STATE_CONFLICT`, `retryable: true`; B's reservation is the tie-breaker when two requests reach it. |
| Learner stops before any response was committed | `Evidence.source_response_id` is a required ID | the stop evidence uses `source_response_id: "session-start"`; B to confirm or add an explicit stop operation to `observe-and-plan`. |
| Crash after B committed, before A stored the commit | recovery queries plan status (8.3) | `GET /internal/v1/plans/{plan_id}` must return `content_hash`, `state_version` and `public_state` when committed; the public result needs the state and the PRD lists only "status and hash". |
| Unexpected internal failure | no `INTERNAL_ERROR` code | `503 LEARNING_UNAVAILABLE`, `retryable: true`; the durable request record makes the retry resume. |
| Unknown session or another caller's session | `FORBIDDEN` 403 | `403 FORBIDDEN` for both, so session IDs cannot be probed. |
| Unknown route or method | no `NOT_FOUND` code | `422 INVALID_SCHEMA` "unknown operation"; a non-`/v1/` prefix gives `400 UNSUPPORTED_VERSION`. |

## Wire shapes A assumes for B's prose-only internal endpoints

The PRD defines `CommitPlanRequest`/`CommitPlanResponse`, `TeachingPlan`, `SessionEnd` and
`Evidence` but describes the other internal bodies in prose. `apps/public_api/clients.py` sends:

- `POST /internal/v1/sessions`: `{schema_version, session_id, request_id, learner_pseudonym,
  goal_concept_id, pace_preference}` and expects `{schema_version, public_state}`.
- `POST /internal/v1/observe-and-plan`: `{schema_version, session_id, request_id,
  expected_state_version, evidence}` (`evidence: null` on the first turn) and expects a
  `TeachingPlan` (with `based_on_state_version == expected_state_version`) or a `SessionEnd`.
- `GET /internal/v1/plans/{plan_id}`: `{schema_version, plan_id, status: pending | committed |
  canceled, content_hash, state_version, public_state}` with nulls when not committed.
- `POST /internal/v1/cancel-plan`: `{schema_version, session_id, plan_id, request_id}` and
  expects `{schema_version, plan_id, status: "canceled"}`.
- Every call carries `X-Trace-Id` and `Authorization: Bearer` from `TUTOR_LEARNING_SERVICE_TOKEN`.

B owns these shapes. Once B's mock ships, the stand-in in
`tests/integration/response/learning_standin.py` is deleted and the tests run against the mock.

## Impact

- No change to B's files or fixtures. `learning_v1.schema.json` is read, never written, by A.
- `tools/response/validate_contracts.py` now also validates the public contract and its fixtures
  under `contracts/fixtures/response/public/`.
- Old artifacts: none exist yet; this is part of the G0 contract freeze.
